# 仅在明确清理请求时使用

普通添加、修改、重建或发布不触发此流程。依赖更新和 Dependabot 也不属于 benchmark 录入范围；若用户提出，应按独立任务处理。

清理分支/工作树前，先列出目标、未提交内容、独有提交、开放 PR 和活跃写入者。保留可恢复证据并核实备份可读；不要把 stash 当作所有文件的备份，它不默认包含 ignored 文件，备份不能泄漏凭据。

只操作请求覆盖且已确认不再被任务使用的目标。脏工作树、锁、重新出现的目录或并发写入先停止该目标的清理，继续不依赖它的工作。不自动 stash 他人改动，不强制删工作树，不因“已经发布”推断分支可以删除。重要删除仍按当前用户授权和宿主权限执行。
